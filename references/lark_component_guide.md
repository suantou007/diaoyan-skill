# 飞书组件使用指南

这份指南回答一个实际问题：

**什么时候该用 callout、table、whiteboard、grid、quote-container？**

目的不是“多用组件”，而是让每种信息都进最合适的容器。

## 1. `callout`

### 适合放什么

- 执行摘要
- 一句话判断
- 核心亮点
- 关键差异 / 风险提醒

### 不适合放什么

- 大段详细正文
- 冗长背景介绍
- 多个互不相关的话题

### 原则

`callout` 适合承载**最先读、最值得记住**的内容。  
它是“重点前置”的容器，不是装饰条。

## 2. `lark-table`

### 适合放什么

- 定价 / 套餐
- 横向能力对比
- 用户类型 / 场景差异
- 结构化参数对比

### 不适合放什么

- 长段分析文字
- 需要强叙事节奏的内容
- 单纯为了“看起来整齐”而硬塞进去的内容

### 原则

只要信息天然是“按行按列对照”的，就优先考虑表格。  
如果内容本质是观点或故事，就不要强行表格化。

## 3. `whiteboard`

### 适合放什么

- 核心工作流 / 用户路径
- 架构图
- 时间线
- 竞品关系图
- 能力地图

### 不适合放什么

- 简单的一张静态截图
- 纯文本结论
- 可以靠普通列表表达清楚的内容

### 原则

当你需要表达的是“关系”而不是“列表”时，用 `whiteboard`。  
尤其适合流程、结构、因果、时间线、竞品版图。

## 4. `grid`

### 适合放什么

- 多步骤截图
- 前后对比
- 输入 vs 输出
- 同一功能的多个稳定状态

### 不适合放什么

- 只有一张图时硬做 grid
- 大量不相关图片拼贴
- 应该用 whiteboard 表达结构关系的内容

### 原则

`grid` 解决的是“并排看”的问题，不是“结构关系”的问题。  
如果图片之间需要比较，就用 grid；如果图片之间需要连线和层级，就用 whiteboard。

## 5. `quote-container`

### 适合放什么

- 用户评价摘录
- 评论平台原话
- 典型正面 / 负面反馈

### 不适合放什么

- 自己总结的话
- 大段研究正文
- 不是引用却写成引用的内容

### 原则

只有当内容真的是“别人说过的话”时，才用 `quote-container`。

## 6. 组件选择的快捷判断

如果你在犹豫，按下面判断：

- **这是最重要的结论吗？** → `callout`
- **这是结构化对照吗？** → `lark-table`
- **这是流程 / 架构 / 时间线 / 关系吗？** → `whiteboard`
- **这是多张图并排比较吗？** → `grid`
- **这是外部原话引用吗？** → `quote-container`

## 7. 一个推荐组合

一份成熟竞品报告通常会这样组合：

1. 顶部 `callout`：执行摘要
2. `whiteboard`：工作流或关系图
3. `grid`：多步骤截图
4. `lark-table`：定价 / 对比
5. `quote-container`：用户评价

## 8. 常见错误

- 用 `table` 塞观点，导致表格像大段文字墙
- 用 `grid` 代替流程图，结果图并排了但关系没表达出来
- 把摘要写在普通正文里，而不是用 `callout` 前置
- 把不是引用的总结硬放进 `quote-container`
- 把所有组件集中到文档末尾，而不是放在所属章节内部
