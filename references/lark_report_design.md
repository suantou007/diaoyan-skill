# 飞书报告设计规范

这份规范用于把飞书交付做成**正式成品**，而不是“把文字和截图塞进文档里”。

参考 `frontend-design` 的思路，但在飞书里要做收敛：不是做网页，而是做**高质量研究文档**。

推荐气质：

- **Editorial / Research Dossier**
- **Strategy Memo**
- **内部汇报版研究报告**

不要做成：

- 纯截图流水账
- 纯大段文字堆叠
- 过度花哨、像海报或营销页

## 1. 飞书文档的视觉目标

飞书正式版报告应该做到：

- 打开第一页就能迅速理解重点
- 有明确的阅读节奏
- 图片、图示、表格和结论互相支持
- 不是只有信息密度，还要有信息组织质量

## 2. 推荐版式节奏

一份成熟的飞书竞品报告，建议按下面节奏组织：

1. **顶部执行摘要 Callout**
   - 一句话定位
   - 3 个核心亮点 / 判断
   - 1–2 个关键不足

2. **产品快照**
   - 用简洁短块呈现：定位、目标用户、主要场景、当前阶段

3. **证据型功能拆解**
   - 一段功能 = 一个小节
   - 标题 → 图片 → 说明 → 竞争意义

4. **流程图 / 时间线 / 竞品关系图**
   - 在正文相关章节中出现，不要集中放到末尾

5. **对比表 / 定价表**
   - 用表格承接结构化信息

6. **开放问题**
   - 单独收口，不和已确认事实混在一起

## 3. 模块设计建议

### 执行摘要

必须放在最顶部，用 callout 承载。  
不要把最重要的结论藏在文档后半段。

### 功能模块

每个功能模块都应具备：

- 清晰标题
- 紧随其后的图片 / 图片组
- 简洁而具体的说明
- 一段“为什么它重要”

### 图示模块

如果用了飞书画板：

- 画板应放在相关章节标题之后
- 文字解释紧跟画板之后
- 不要把图放得离正文太远

### 表格模块

表格用于：

- 定价 / 套餐
- 横向能力对比
- 用户类型 / 场景差异

不要用表格承载长段论述。

## 4. 图片与图的节奏

推荐顺序：

1. 标题
2. 图片 / grid / 画板
3. 解释
4. 判断

不要先写一大段，再在很后面补图。

## 5. 风格原则

- 结论前置
- 层级清楚
- 一屏一重点
- 同类信息用同类容器
- 图文相互支撑

## 6. 与 HTML 的关系

`notes.html` 偏“本地正式交付页”  
飞书文档偏“协作与汇报载体”

两者都应该像正式成品，但飞书更强调：

- 协作可读性
- 层级清晰
- 评论和后续编辑便利
