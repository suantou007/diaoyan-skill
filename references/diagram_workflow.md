# 图示交付：SVG → 飞书画板

当竞品调研需要表达**流程、时间线、架构、竞品关系、能力地图**时，优先补一张图。

默认推荐链路：

1. 本地生成 SVG
2. 通过 Lark / whiteboard CLI 转成飞书画板
3. 将画板插入飞书文档对应章节

这样交付出来的是**可编辑**流程图，而不是一张死图。

## 什么时候应该补图

以下内容只靠文字通常不够清楚，建议补图：

- 核心工作流 / 用户路径
- 多阶段生成管线
- 产品能力模块关系
- 产品演进时间线
- 横向竞品格局或关系图

## 默认图示位置

图不是装饰，而是正文的一部分。默认位置如下：

- **工作流图**：默认放在“产品核心功能”章节的最后一个小节里，标题可写成“核心工作流 / 用户路径”
- **时间线图**：放在“横纵分析 > 纵向演进”标题后或第一小节后
- **竞品关系图 / 能力地图**：放在“横纵分析 > 横向竞品对比”开头，用来先建立全局视角

不要把所有图集中堆到文档末尾。

## 推荐路径

### 路径 A：复杂流程 / 架构 / 竞品关系图

默认优先：

**SVG → whiteboard OpenAPI JSON → 飞书画板**

适用场景：

- 布局要求高
- 节点较多
- 需要更自由的视觉组织

### 路径 B：简单标准流程

如果只是简单流程、标准时序或普通图，可以接受：

**Mermaid → 飞书画板**

但对于竞品分析里的关键流程图，默认仍优先 SVG，因为可控性更高。

## 飞书画板写入思路

优先复用 `lark-whiteboard` skill，不要在本 skill 里重写整套画板逻辑。

高层步骤：

1. 确定图表类型（流程图 / 时间线 / 关系图 / 架构图）
2. 本地生成 SVG
3. 通过 whiteboard CLI 转成 OpenAPI JSON
4. 用 `lark-cli whiteboard +update --source - --input_format raw --as user` 写入飞书画板
5. 预览确认布局后，再插入或关联到飞书文档对应章节

## 与正文的关系

图和文字要配套：

- 图先建立结构
- 文字再解释关键节点、差异和判断

推荐顺序：

1. 章节标题
2. 飞书画板 / 图
3. 解释文字
4. 结论 / 竞争意义

## HTML 兜底

如果最终没有飞书，可在 `notes.html` 中直接插入 SVG 或导出后的 PNG。

顺序也保持一致：

1. 标题
2. 图
3. 文字

不要让图脱离所属章节单独堆到页面底部。
