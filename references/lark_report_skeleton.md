# 飞书报告骨架模板

下面是推荐的飞书报告骨架。不是要求逐字照搬，而是建议把文档组织成这种结构和阅读节奏。

## 1. 顶部执行摘要

```markdown
<callout emoji="📌" background-color="light-orange">
**一句话介绍**：这里用一句话说清楚产品是谁、服务谁、主打什么。

**核心亮点**
1. ...
2. ...
3. ...

**关键差异 / 不足**
1. ...
2. ...
</callout>
```

## 2. 产品快照

适合用短段落或轻量 list，不要一上来就长篇大论。

建议内容：

- 产品定位
- 目标用户
- 核心场景
- 当前阶段
- 关键标签

## 3. 证据型功能拆解

每个功能 section 推荐遵循：

```markdown
## 1. 功能标题

[这里放图片 / grid]

时间戳：00:01:24 - 00:01:42

**视频观察**
...

**网页确认**
...

**推断 / 开放问题**
...

**竞争意义**
...
```

### 多步骤流程

如果一个功能包含多个稳定状态：

```markdown
## 2. 多步骤流程标题

<grid cols="2">
  <column width="50">[图 1]</column>
  <column width="50">[图 2]</column>
</grid>

后面再写解释。
```

## 4. 核心工作流 / 用户路径

推荐：

```markdown
## 核心工作流 / 用户路径

[这里放飞书画板 / 流程图]

这里再解释步骤、分叉点和关键设计。
```

## 5. 纵向演进（完整竞品分析时）

```markdown
## 纵向演进

[这里放时间线图]

正文展开关键节点。
```

## 6. 横向对比（完整竞品分析时）

```markdown
## 横向对比

[这里放竞品关系图 / 能力地图]

<lark-table>...</lark-table>
```

## 7. 定价 / 套餐

```markdown
## 定价 / 套餐

<lark-table>...</lark-table>
```

## 8. 开放问题 / 未确认项

文档最后单独开一节：

```markdown
## 开放问题 / 未确认项

1. ...
2. ...
3. ...
```

## 核心原则

- 标题之后先放图，再写解释
- 重要判断尽量前置
- 图示和表格都要出现在所属章节内部
- 不要把所有截图、所有图、所有表堆到末尾
