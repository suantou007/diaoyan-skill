# `notes.html` 设计规范

这份规范参考了 `frontend-design` skill，但做了适合竞品调研交付的收敛：

- 要**像正式成品**
- 要**可读**
- 要**有设计感**
- 但不要做成花哨 landing page

推荐的总体方向不是“营销官网”，而是：

**Editorial / Research Dossier / Strategy Memo**

也就是：像一份高质量研究报告网页，而不是产品宣传页。

## 1. 视觉方向

优先选择以下气质之一，并保持统一：

- **编辑部 / 杂志感**：大标题、留白、强层级、沉稳配色
- **策略备忘录**：理性、清晰、结构感强、重点突出
- **轻量数据简报**：适合带时间线、流程图、对比卡片

避免：

- 俗套的紫色渐变 AI 风
- 过多发光、玻璃、悬浮粒子特效
- 看起来像 SaaS 官网 hero 的开屏

## 2. 页面结构

推荐的 `notes.html` 页面结构：

1. **Hero / 封面区**
   - 产品名
   - 一句话判断
   - 分析日期 / 来源视频 / 官方网址

2. **执行摘要**
   - 3–5 条最值得看的结论
   - 可以做成 callout / insight card

3. **产品快照**
   - 产品定位
   - 当前阶段
   - 主要场景
   - 关键标签

4. **证据型功能拆解**
   - 每个功能一个 section / card
   - 顺序固定：标题 → 图片 → 时间戳 → 视频观察 → 网页确认 → 推断 → 竞争意义

5. **核心工作流 / 用户路径**
   - 放流程图或步骤图

6. **纵向演进**（如果是完整竞品分析）
   - 放时间线图或时间轴列表

7. **横向对比**（如果是完整竞品分析）
   - 放竞品关系图 / 对比矩阵

8. **开放问题 / 未确认项**
   - 单独列出，避免和已确认事实混在一起

## 3. 图片与图的位置

页面内所有视觉元素都遵守同一规则：

- **功能截图**：放在所属功能标题下、正文说明前
- **流程图**：放在“核心工作流 / 用户路径”标题下
- **时间线图**：放在“纵向演进”标题下
- **竞品关系图 / 能力地图**：放在“横向对比”标题下

不要把所有图集中堆到页面底部。

## 4. 版式建议

### Hero 区

- 左侧放标题和一句话判断
- 右侧放 meta 信息块
- 背景可以有轻微纹理或淡层次，但不要喧宾夺主

### 正文区

- 单栏主阅读流即可
- 如果内容多，可加一个简洁目录
- 每个 section 保持明显间距

### 功能卡片

每个功能卡片建议包含：

- 标题
- 截图或图片组
- 时间戳 pill
- “视频观察 / 网页确认 / 推断”三段
- 一段“为什么这件事重要”

## 5. 字体与配色

不要默认 Arial / Inter 式无差别审美。

建议：

- 标题：有性格的 serif 或 display 字体风格
- 正文：中性、清晰、耐读
- 用 CSS variables 管理颜色

配色建议：

- 主色保持克制
- 用 1 个强调色点关键结论
- 背景和卡片层级分明

## 6. 动效与技术取舍

`notes.html` 是交付页，不是炫技页。

建议：

- 以静态 HTML + CSS 为主
- 允许少量 hover / reveal 效果
- 不依赖复杂 JS 才能阅读

## 7. 直接可用的模板

优先从 [assets/notes_template.html](../assets/notes_template.html) 开始，再按具体项目替换内容和资源路径。
