# 检查清单

## 正式报告完整性

- 已读取并覆盖 `references/reference_doc_structure.md`
- 顶部执行摘要 Callout 有观点、有比较，不是中性百科
- Callout 后还有足够厚的总括段，不是只写完 callout 就结束
- 公司与团队、融资、用户/客户/流量、产品定位、核心功能、定价、产品评价、Demo 视频、相关链接均已整理
- 查不到的信息已显式写“未找到 / 未核验 / 视频未展示”，没有静默删除
- 深度竞品/正式报告已检索用户 skill 库中的调研相关 skill（例如 `hv-analysis`），并在 manifest 中记录使用/跳过原因；不可用时已说明降级
- “横纵分析”章节已经成型，内部至少覆盖：纵向演进、横向竞品对比、交汇洞察
- 纵向演进、横向对比、横纵交汇洞察不是一段短摘要，而是由被选中的研究 skill/框架辅助形成的独立内容
- 标题按能力主题合并，数量受控，没有把微小操作拆成一串碎标题
- 每个大节结尾都有收束判断，不是只摆事实
- 写正文前已经完成“视频动作 → 能力主题”的归并
- 总表承担导航作用，正文承担主要分析作用，没有拿总表替代正文

## 证据完整性

- 视频里看到的内容已标成“视频观察”
- 网页核验过的内容已标成“网页确认”
- 推断内容已标明，或被删除
- 凡是由截图支撑的结论都带了时间戳

## LLM 图像输入安全

- 已运行 `scripts/prepare_llm_images.py` 生成 `llm_images/manifest.json`
- 发给模型或子 agent 的图片只来自 `llm_images/`
- 没有发送原始截图、原始 contact sheet、base64 图片或 `detail: "original"`
- 单次子 agent 输入最多 1–2 张安全图；更长视频已拆批

## 截图质量

- 选中的截图是稳定画面，不是过渡态
- 多步流程在需要时使用了多张图
- 截图文件名有顺序且有意义
- 图片出现在所属功能表格行 / 所属功能小节内部，而不是被堆到文档底部或单独的“证据拆解”章节
- 图片位于对应说明文字之前，读者能先看图再读解释
- 每张图都带有简洁备注，说明这张图想让读者看见什么
- 图注足够简洁，没有“用于证明 / 证据如下 / 时间戳 / 来源”这种堆信息式写法
