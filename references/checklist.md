# 检查清单

## 正式报告完整性

- 已读取并覆盖 `references/reference_doc_structure.md`
- 顶部“一句话总结”Callout 覆盖一句话定位、一句话亮点、一句话现状描述
- 基本信息表覆盖产品名、所属公司 / 团队、上线时间、平台、产品定位、目标用户、关键数据、官网 / 下载
- 产品简介为 150–250 字自然段，说明产品是什么、解决什么需求、主体验是什么、当前阶段
- 核心功能体验按“小标题 → 简述 → 体验截图 → 截图描述 → 一句点评”展开
- 亮点与不足聚焦本产品自身体验，总数控制在 6 条以内
- 竞品对比覆盖本产品和同赛道 2–3 个产品；无法判断赛道时已写“待补充”
- 结论与跟踪建议包含一句话核心判断和 2–3 个跟踪变量
- 尾部已增加“一致性检查”
- 查不到的信息已显式写“未公开 / 未找到 / 未核验 / 视频未展示”，没有静默删除字段或模块
- 正式报告已检索当前会话可用 skills；必要时用 `tool_search` 发现调研相关 skill，并在 manifest 中记录使用/跳过原因；不可用时已说明降级
- 核心功能体验优先选“与竞品差异最大”和“用户感知最强”的模块，没有流水账式全覆盖
- 写正文前已经完成“视频动作 → 能力主题”的归并

## 一致性检查

- 基本信息里的“产品定位”和结论里的“核心判断”一致；不一致时已修正
- 亮点都能在核心功能体验里找到对应支撑；找不到时已补充截图/描述或删除该判断
- 不足都能在核心功能体验或“未展示 / 未核验”记录里找到依据；找不到时已补充截图/描述或删除该判断
- “一句话总结”里的亮点能在“亮点与不足”或“核心功能体验”里找到支撑

## 证据完整性

- 视频里看到的内容已标成“视频观察”
- 网页核验过的内容已标成“网页确认”
- 推断内容已标明，或被删除
- 凡是由截图支撑的结论都带了时间戳

## LLM 图像输入安全

- 已运行 `scripts/prepare_llm_images.py` 生成 `llm_images/manifest.json`
- 发给模型或子 agent 的图片只来自 `llm_images/`
- 没有发送原始截图、原始 contact sheet、base64 图片或 `detail: "original"`
- 单次子 agent 输入最多 1–2 张安全图；更长视频已拆批

## 截图质量

- `selected_screenshots/` 至少保留了 16 张候选稳定截图
- 候选截图覆盖了入口、输入、生成、编辑、结果总览等关键阶段，而不是只截 3–4 个孤立节点
- 选中的截图是稳定画面，不是过渡态
- 多步流程在需要时使用了多张图
- 截图文件名有顺序且有意义
- 图片出现在所属核心功能体验模块内部，而不是被堆到文档底部或单独的“证据拆解”章节
- 图片位于对应说明文字之前，读者能先看图再读解释
- 每张图都带有简洁备注，说明这张图想让读者看见什么
- 图注足够简洁，没有“用于证明 / 证据如下 / 时间戳 / 来源”这种堆信息式写法

## 网页核验

- `analysis_manifest.json` 已把 Tavily 与 WebSearch 的分工写清楚
- 产品事实优先使用了官方来源
- 评论和市场信号与官方表述分开写
